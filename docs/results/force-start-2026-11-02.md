# Force Start — 2026-11-02

## Research and decisions

- qBittorrent exposes a Boolean Force Start setting and forced transfer states: [official API](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-%28qBittorrent-5.0%29#set-force-start).
- libtorrent excludes forced torrents from automatic admission and normal active-slot accounting: [official queue documentation](https://www.libtorrent.org/manual-ref.html#queuing).
- Transmission exposes Start Now separately from ordinary Start: [official RPC specification](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md#31-torrent-action-requests).
- Native checkable commands, meaningful disabled states, and shared menu terminology follow [Apple menu guidance](https://developer.apple.com/design/human-interface-guidelines/menus).

SeedHop uses rqbit, not libtorrent. Its own queue controller implements this feature without vendor changes. The user chose persistence across restart and respect for scheduled suspension.

## Delivered behavior

Force Start resumes a healthy transfer and exempts it from the download queue without occupying a normal slot. Queue position remains unchanged. Scheduled suspensions, all speed limits, verification, storage checks, and operation locks remain effective. It does not create peers or guarantee faster downloads.

An atomically saved, default-empty `force_started` set extends `queue.json`. Old files remain readable. Pause and Resume clear the override; clearing Force Start alone does not pause the transfer. Completion, recheck, relocation, retry, and ordinary shutdown preserve it. Removed or re-added torrents do not inherit stale overrides.

Protocol 8 adds an explicit Boolean `forceStart` request and `forceStarted` snapshot field across the native host and both bridge snapshot paths. A request with no Boolean is rejected. Swift bindings are regenerated by the normal build.

The transfer context menu provides on/off/mixed states and captures the action's targets and value. The Transfers menu exposes the same action. Queued inspector actions expose Force Start; forced inspectors expose Use Normal Queue. Rows show a bolt while keeping their primary status. Accessible labels include the override. All new UI text has translations in the 13 supported languages; translation provenance marks these as AI drafts, not human-reviewed translations.

## Validation

Passed during implementation:

- Four dedicated Force Start integration tests: queue bypass and slot accounting, ordering and restart, Pause/Resume, repeated commands, unlimited mode, scheduled suspension, bandwidth profiles, completion, recheck, relocation, failed saves, unavailable destinations, old queue files, removal and re-addition.
- Six scheduling and three existing management regressions.
- Five bridge tests, including typed/JSON override snapshots and explicit clearing.
- Twenty-eight core unit tests, six import-option tests, twelve recovery tests, and one status regression.
- Workspace Clippy with warnings denied.
- Catalog coverage and placeholder checks: 716 entries across 13 languages; four localization tooling tests.

The real disk-full status test is ignored by default and was not run with a disposable disk image.

- Native arm64 development build and deep, strict code-signing verification passed. This is an ad-hoc development build, not a distribution release.
- All 63 UX presentation regressions passed, including captured Force Start targets, partial failure, eligibility, primary status, snapshot compatibility, and explicit Boolean requests.
- Real packaged XPC verification passed, including Force Start enable/clear, omitted-Boolean rejection, protocol 8, and the existing restart, scheduling, import, recheck, cancellation, relocation, and removal scenarios.
- Native fixture menu actions passed for Force Start off/on/mixed states, captured targets, bulk enable/clear, and retained pause controls. Existing transfer selection, controlled Return activation, sorting, column persistence, and reset checks also passed.
- The built app's 92 runtime localization checks passed.

Manual pointer/keyboard acceptance and VoiceOver remain unverified. Controlled native menu actions and presentation tests do not certify those walkthroughs.
